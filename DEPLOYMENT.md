## 2 â€” Render (Backend)

### Connect

1. Push the repo to GitHub.
2. Go to **Render â†’ New â†’ Blueprint** and import the repo root.  
   Render will auto-detect `render.yaml` and create the `feelinga-tea-api` service.

### Environment Variables to Set Manually

Set these in **Render â†’ Environment** (marked `sync: false` in `render.yaml` â€” they are intentionally not stored in the file):

| Variable | Value |
|---|---|
| `MONGODB_URI` | Atlas connection string |
| `CLIENT_URL` | Your Vercel URL e.g. `https://feelinga-tea.vercel.app` |
| `ADMIN_EMAIL` | The email address that gets admin role on first login |
| `GOOGLE_CLIENT_ID` | From [Google Cloud Console](https://console.cloud.google.com/) â†’ Credentials |
| `EMAIL_FROM` | e.g. `"Feelinga Tea" <noreply@yourdomain.com>` |
| `SMTP_HOST` | Your SMTP provider host |
| `SMTP_USER` | SMTP username |
| `SMTP_PASS` | SMTP password |
| `HUNTER_API_KEY` | Only required if `EMAIL_VERIFIER_PROVIDER=hunter` |

> **Note:** `JWT_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by Render (`generateValue: true`).  
> Do **not** set them manually â€” Render will rotate them on first deploy.

### Verify

Once deployed, hit `https://feelinga-tea-api.onrender.com/api/v1/health` â€” you should see:

## 3 â€” Vercel (Frontend)

### Connect

1. Go to [vercel.com](https://vercel.com) â†’ **New Project** â†’ Import the GitHub repo.
2. Vercel will detect `vercel.json` at the repo root and automatically set:
   - **Root Directory:** `next-frontend`
   - **Framework:** Next.js
   - **Build Command:** `npm run build`

### Environment Variables to Set

Go to **Vercel â†’ Project â†’ Settings â†’ Environment Variables** and add:

| Variable | Value | Environments |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://feelinga-tea-api.onrender.com` | Production, Preview, Development |
| `NEXT_PUBLIC_SITE_URL` | `https://feelinga-tea.vercel.app` | Production only |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | Google OAuth client ID | All |

> **Note:** `NEXT_PUBLIC_SITE_URL` for Preview environments can be left unset â€” the layout.tsx  
> automatically falls back to `VERCEL_URL` for canonical URLs.

### Verify

1. Trigger a deployment from the Vercel dashboard.
2. Visit your Vercel URL â€” the site should load and API calls should resolve.
3. Check the **Network** tab for `/api/v1/health` â†’ should return `200`.

## 4 â€” Google OAuth Setup

1. Go to [Google Cloud Console](https://console.cloud.google.com/) â†’ **APIs & Services â†’ Credentials**.
2. Create an **OAuth 2.0 Client ID** (Web application type).
3. Add **Authorized JavaScript Origins:**
   - `https://feelinga-tea.vercel.app`
   - `http://localhost:3000` (for local dev)
4. Add **Authorized redirect URIs** (only if using server-side OAuth flow â€” not needed for client-side):
   - `https://feelinga-tea-api.onrender.com/api/v1/auth/google/callback`
5. Copy the **Client ID** â†’ set as `GOOGLE_CLIENT_ID` (Render) and `NEXT_PUBLIC_GOOGLE_CLIENT_ID` (Vercel).

## Common Issues

### CORS Error on Production

Make sure `CLIENT_URL` on Render is set to **exactly** your Vercel URL (no trailing slash).  
Example: `https://feelinga-tea.vercel.app` âœ… not `https://feelinga-tea.vercel.app/` âŒ

### Render Cold Starts

Render's free tier spins down after 15 minutes of inactivity. The first request may take 30â€“60 seconds.  
The frontend `api.ts` shows a user-friendly "Server is waking up" message automatically.

### Images Not Loading

The `next.config.mjs` adds the Render API host to `images.remotePatterns` dynamically from `NEXT_PUBLIC_API_URL`.  
Make sure this env var is set correctly on Vercel.

### Stale `dist/` on Render

If you see `[start-guard] Refusing to start with stale dist/ artifacts`, Render's build command  
(`npm ci && npm run build`) should have run before `npm start`. Check the Render build log.
